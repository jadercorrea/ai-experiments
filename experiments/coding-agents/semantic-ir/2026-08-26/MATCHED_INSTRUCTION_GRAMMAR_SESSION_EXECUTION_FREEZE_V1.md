# Matched Instruction-Grammar Session Execution Freeze v1

## Outcome

Calibration 008 is now frozen as a provider-ready but call-free matched
execution. The candidate integrates Session Instruction Grammar v1 into both
the request builder and the dispatch runtime while preserving the complete
Calibration 007 subject outside the reserved-phase grammar.

The retained local preflight passes all eleven callable references: 110/110
work-phase requests are byte-identical to the previous freeze, 11/11 reference
mutations cross commit, 11/11 sessions terminate under exact `F[]`, and the
shared hidden evaluators pass 6/6 source plus 5/5 supported semantic cells. A
synthetic extra-argument `F` is rejected by the exact advertised request schema
before dispatch.

No model call occurred, no launch artifact exists, and no prior authorization
is inherited. Calibration 008 still requires `explicit_launch_008`.

## Frozen intervention

The first ten turns retain the exact generic Session ISA tool bytes from
Calibration 007. Only the two reserved phases change:

- commit advertises the still-budgeted, opcode-discriminated `E/S/F` union,
  including exact arity and source or semantic `S` payload grammar;
- finish advertises only exact `F` with an empty positional argument array;
- an exhausted opcode removes its complete branch and payload definitions;
- both matched arms receive the same generated schema; and
- decoded instructions are validated against the exact request-time schema
  before the existing progress checks and runtime dispatch.

The runtime backstop is intentional. The model-visible grammar and the
accepted runtime language are the same object rather than two separately
maintained approximations. A request-schema violation becomes the recoverable
tool error `session_instruction_grammar_invalid` and does not reach the
underlying Session ISA dispatcher.

## Isolation from Calibration 007

The freeze reuses the exact six instances and twelve-cell schedule from
Calibration 007. It preserves the following experimental-subject fields:

- initial user message, task bytes, static context, and static tool asset;
- provider model, sampling, limits, schedule order, and stopping rule;
- source and semantic memory policies;
- progress-phase schedule, accounting, isolation, and analysis policy; and
- hidden evaluators and reference patches, which remain excluded from model
  context.

Administrative identifiers, runner and dependency hashes, launch contract,
preflight evidence, and contamination date necessarily change. The sole
model-visible experimental delta is the complete instruction grammar during
commit and finish.

This is a within-instance follow-up, not a fresh benchmark. The exact instances
had already produced 127 provider responses before this freeze. That exposure
is recorded explicitly and must remain part of any later interpretation.

## Gateway transport gate

The selected local adapter forwards the OpenAI-style function `parameters`
object into Bedrock's `toolSpec.inputSchema.json` without structural change.
The preflight verifies identity for the commit and finish schemas and observes
the required `oneOf`, `const`, `prefixItems`, and `items` keywords after local
translation.

That gate proves adapter transport only. It does **not** establish that Bedrock
accepts every keyword, preserves it beyond the submitted request, constrains
decoding with it, or causes the model to obey it. Provider acceptance and model
adherence remain unobserved until a separately authorized launch.

## Frozen hypothesis

Calibration 007 showed that exposing a final-turn `F` opportunity changed
action selection, but three sampled `F` calls still carried forbidden
arguments. Calibration 008 asks whether complete request-time lexicalization
converts more forced terminal choices into valid terminals, and whether any
reliability gain justifies the larger commit schema.

The primary descriptive checks remain:

1. valid provider-call terminals and hidden passes by arm;
2. grammar errors, especially extra-argument `F` attempts;
3. output, input, and total tokens under the unchanged schedule; and
4. estimated cost relative to Calibration 007.

Because the instances are repeated and the intervention changes disclosed
schema bytes, a future result remains descriptive. It cannot isolate a general
representation effect or treat token/cost differences as a pure grammar cost.

## Claim boundary

- The freeze proves deterministic construction, local reference compatibility,
  exact-schema runtime enforcement, and local adapter identity.
- Known references are construction fixtures, not measurements of model
  performance.
- No provider acceptance, constrained decoding, counterfactual choice, Pass@1,
  latency, token, cost, or efficacy result is established here.
- The previous Calibration 007 launch record authorizes nothing in this
  package.
- There is deliberately no `launch.json` or observation directory for
  Calibration 008.

The experimental-TDD state is now:

`instruction-shape lexicalization passed -> request/runtime identity passed -> matched execution frozen -> provider behavior untested`
