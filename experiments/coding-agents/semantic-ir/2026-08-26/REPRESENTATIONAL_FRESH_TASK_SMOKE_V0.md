# Representational fresh-task smoke v0

## Status

**The complete local eligibility pipeline passed for five persisted development
fixtures, one attempt-zero slot per family.** The builder created five baseline
repositories, five references, public and hidden evaluator plans, five
canonical observations, and twenty participant realizations. No model call or
provider request occurred.

This is an engineering vertical slice, not the beginning of the confirmatory
cohort. Persisting and inspecting these subjects exposes them to the development
process. Their five attempt-zero candidates are therefore retained as evidence
but are ineligible for confirmation; construction for those slots must resume
at the already predeclared attempt 1.

## What passed locally

Each family fixture passed the seven-step construction pipeline within the
current provider-free boundary:

1. its bytes were deterministically materialized from the locked generator and
   attempt seed;
2. both baseline and reference remained within the frozen program operations,
   catalog symbols, and Session ISA;
3. the reference passed every public and hidden value/effect case while the
   baseline was discriminated by both partitions;
4. all four observation surfaces decoded to the same canonical bytes;
5. meaningful and opaque lexical skeletons matched within nested and table
   packaging;
6. participant trees excluded references, hidden cases, condition labels, and
   the evaluator-only codebook; and
7. the complete smoke tree, including tasks, evaluators, realizations, audit
   reports, and dependencies, was content locked.

## Provisional contamination audit

The audit inventoried 867 historical `request*.json` artifacts under the
experiment observations, representing 832 unique raw request digests and 966
unique extracted participant-text digests. None equalled any of the twenty new
participant-tree digests. All twenty tree digests and all five semantic task
signatures were distinct.

This result is deliberately labelled provisional. The future provider request
envelope has not yet been frozen, so the final comparison unit does not exist.
The current audit compares deterministic participant-tree bytes against raw
historical requests and their extracted participant text; it must be repeated
over the exact outbound request bytes before launch.
